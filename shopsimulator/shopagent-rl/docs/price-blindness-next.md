# 价格盲视：诊断证据与下一步设计（2026-08-15）

> 状态：**D1–D3 已完成，按预注册规则选定 E1（合成约束违反数据注入）**。
> 诊断结果见 §5，前置结论见 [`counterfactual-eval.md`](counterfactual-eval.md)。

## 1. 新证据：失败层级重新定位

对 `outputs/counterfactual/cf_c1hard_s200.jsonl` 的 cf 侧（price>budget）145 条
逐一分析模型 Thought 文本：

- **145/145 同时复述了价格与预算两个数字**——模型"读得到"价格，观测不缺信息
  （`obs_format.py` 也已把 `当前价格:` 作为独立字段行输出）；
- **96/145 在价格超预算时口述"符合预算/在预算内"**，比较结论是假的：
  「价格1575元，符合预算约1300元」「价格11元，符合5元以内预算」；
- 29/145 出现"超过/超出"字样但 28/29 仍然 `click[buy now]`。

结论：瓶颈不是观测读取（C1-hard 文档里"观测侧不可辨识"的猜测**不成立**），
而是 **数值比较判断 + Thought 合理化**：模型把"属性都匹配"的先验直接外推到
价格维度，复述数字但不执行比较。hard 归零惩罚无法惩罚到"错误的比较语句"，
只惩罚到最终的购买动作，所以只学到了"少买"。

## 2. 诊断实验（D1–D3，全部离线，先跑完再定分支）

### D1 纯比较能力探针（<30 min，单卡 vLLM）

同一组数字对（近距/远距、价格在上/在下，各 50 对，真实任务价格分布采样），
两种问法对照：

- 算术式：`1575 是否不超过 1300？`
- 购物式：`商品价格1575元，我的预算是1300元，可以购买吗？`

对 Base / SFT v1 / GRPO v2b / GRPO C1-hard 四 checkpoint 各跑一遍。

**判读**：算术式对而购物式错 → 情境先验压制（策略把"匹配"先验外推），
走 E2；两种都错 → 数字比较能力缺失（1.7B 已知弱点），走 E1 或 E3。

### D2 探测侧提示增强 A/B（<1 h，只改探测 prompt，不改权重）

在 212 对 cf 探测上加两个变体（与 baseline 同 checkpoint、同 greedy）：

- **b) salience**：观测末尾并排追加「当前价格: X 元 / 预算上限: Y 元」
  （信息等价，仅提高显著性，不给结论）；
- **c) 指令**：系统提示加一条通用规则「购买前必须先比较价格与预算，
  超出预算时不得点击购买，应重新搜索」（不泄露每题答案）。

**判读**：c 修复而 b 不修复 → 是"没做这个动作"而非"做不了"，最便宜的
修复是提示工程（E-zero）；b、c 都不修复 → 判断在权重里，必须训练（E1/E2）。

### D3 训练信号审计（CPU，日志/轨迹统计）

从 c1_hard 训练产物统计"真实购买且超预算"（hard zero 真实触发）的频率与
步数分布。训练日志 reward 分布显示 reward=0 有 466 次，但其中多少是
超预算购买（而非非法动作/放弃/买错）未知。

**判读**：若 hard zero 触发率 < 1% rollout → on-policy 探索几乎不覆盖
该状态，RL 从未见过可学习的对照（解释训练 0.995 vs 探测 0.000 的
泛化差），E2 的"低预算 cohort"直接针对此。

## 3. 干预分支（预注册，按 D1–D3 结果走一条）

### E-zero（若 D2c 修复）：系统提示预算检查规则

改 AgentLoop 系统提示，重评 Final-200 + 212 对 cf。零训练、半天出结果。
主判据：price cf accuracy 从 0 起来且 Final-200 strict 不低于 16%
（=18% − 噪声带）。通过后再考虑是否值得训练固化。

### E1（若 D1 两种问法都错）：合成约束违反数据注入

用反事实生成器（`scripts/build_counterfactual_pairs.py`）批量构造
超预算/规格不符状态，正确动作由构造时已知（SEARCH_ALTERNATIVE 等），
无需 teacher 模型：

- 生成 1–2k 条「超预算状态 → 正确 Thought（真实口述比较结论）→ search 动作」
  的单轮样本，混入 SFT 数据重训 adapter，再续跑短程 GRPO；
- 样本中的 Thought 必须包含正确的比较语句（「1575 > 1300，超出预算」），
  直接教第 1 节发现的"说谎语句"。

### E2（若 D1 购物式错、算术式对）：低预算 cohort 训练

GRPO v3：在 c1_hard 配方基础上，把一部分训练任务的 `price_upper` 压到
目标价的 50–70%，使 on-policy rollout 高频到达"目标商品必然超预算"的
提交点——hard 信号在该状态密集触发，且正确的出路（search 替代品）真实
存在于环境中。评测时用原始预算任务 + 212 对 cf，确认没有为低预算任务
过拟合。此分支同时要求 D3 确认原始信号稀疏。

### 通用闸门

- 所有分支统一判据：212 对 cf 的 `price_above_budget cf accuracy`
  （当前 0.000）为主，Final-200 strict ≥ 16% 为不回退线；
- 不允许在 212 对探测集上调 prompt/超参后又在同一集合上宣称泛化——
  D2/E-zero 的 prompt 变体若要外推，需再生成 v2 持留对集（生成器换
  random seed，任务不重叠）复核；
- 单卡互斥：所有 vLLM 评测/训练串行，后台脱离执行。

## 5. 诊断结果（2026-08-15，产物在 `outputs/price_blindness/`）

### D1 比较探针（580 题/checkpoint，greedy）

| checkpoint | 算术式·预算内 | 算术式·超预算 | 购物式·预算内 | 购物式·超预算 |
|---|---:|---:|---:|---:|
| Base | 0.766 | 0.290 | 1.000 | 0.000 |
| SFT v1 | 0.531 | 0.276 | 0.979 | **0.359** |
| GRPO v2b | 0.759 | 0.172 | 1.000 | 0.000 |
| GRPO C1-hard | 0.697 | 0.262 | 1.000 | 0.000 |

- 纯数字比较在所有 checkpoint 上都弱（超预算方向仅 0.17–0.29，普遍
  yes-bias），训练没有改善它；
- **SFT 是唯一在购物式超预算上非零的 checkpoint（0.359），GRPO 之后归零**：
  RL 把"可以买"先验强化到完全覆盖 SFT 数据带来的那点价格敏感；
- 结论：按 §3 预注册判据属"两种问法都失败"→ 走 **E1**；且 E1 必须把正确
  比较语句注入完整 agent 格式（页面 + Thought + 动作），因为 SFT 的 0.359
  在完整探测语境下也是 0——语境先验会覆盖孤立能力。

### D2 prompt 变体（C1-hard，212 对）

| 变体 | price cf acc | price commit err | overall orig acc |
|---|---:|---:|---:|
| baseline（§C1-hard 节） | 0.000 | 0.330 | 0.462 |
| salience（价格/预算并排） | 0.007 | 0.166 | **0.274** |
| instruct（系统提示规则） | 0.000 | 0.262 | **0.326** |

两个变体的 commit err 下降都伴随 overall orig acc 大幅下降——模型只是
变得更不敢买，价格条件化行为没有出现。**E-zero 分支关闭**。

### D3 hard-zero 触发审计

c1_hard 训练全程 423/6400 rollout（6.6%）真实触发归零；按十分位
10.5%→…→8.4%，信号持续存在且不稀疏。**E2 的"探索覆盖不足"前提不成立**，
E2 关闭。

### 分支决定

D1 双失败 + D2 双失败 + D3 排除 E2 → **执行 E1**：用反事实生成器从
训练任务池（非 final200）批量构造超预算状态，正确动作由构造已知
（SEARCH_ALTERNATIVE），Thought 中写入真实比较语句（"1575 > 1300，超出
预算"），以完整 agent 格式混入 SFT 重训，再以 hard 模式续跑 GRPO（合成
状态同时进入 GRPO 任务混合，防止 RL 再次覆盖）。评测：换 seed 的 v2
持留对集 + Final-200，闸门为 price cf accuracy ≥ 0.3 且 strict ≥ 16%。

## 6. E1 首次实现审计与 v4 修正（2026-08-17）

E1-v3 不能算成功。虽然训练目标 Thought 显式写入正确比较，数据构造却把
`任务约束摘要` 只追加到超预算负例，并默认只生成 counterfactual 侧。结果是：

- heldout-v2 自然 price cf accuracy：0.000；
- price commit persistence error：0.9427；
- 恢复训练 summary 后 price cf accuracy：1.000；
- 同一 summary 诊断中的 price original accuracy：0.3255。

这不是“模型完全不会执行恢复动作”，而是“模型把 summary presence 当成恢复动作开关”。
E1 的首次实现因此作为失败消融保留，不能用于支持价格反事实创新。

v4 corrective 做三项修正：

1. 每个价格 pair 同时生成预算内 original 与超预算 counterfactual；
2. 两侧均使用自然 observation，不追加 hidden/canonical summary；
3. 加入带 summary 但仍应 `COMMIT` 的 nuisance-positive 样本，主动破坏旧触发器。

当前 v4 从 v3 LoRA 继续训练 1 epoch（1,258 steps）。完成后自动运行自然 heldout-v2；
price cf <0.30 立即停止，达到后再跑 Final-200，strict <0.16 仍停止。任何情况下都不会
自动启动 GRPO。另需在最终统计前核对自然指令预算与内部 `goal.price_upper` 的一致性。
